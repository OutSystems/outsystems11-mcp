# Reactive Screen & Widget Creation via `applyModelApiCode` — Verified Mechanics + Crash Traps

**Status**: Live-verified building a full Reactive app from scratch + probing StyleGuidePreview. These are the exact API entry points and the runner-crash traps that cost debug cycles to isolate.
**Companion**: [`osui-verified-blocks.md`](osui-verified-blocks.md) (which OutSystemsUI blocks to compose + design tokens), [`patterns-by-element.md`](patterns-by-element.md) (entity/action/node basics).

## Runner-crash traps (symptom: response with empty `stdoutOutput` AND empty `mutatedOmlPath`, no exception — an uncatchable sidecar crash; the mutation rolls back)
Each of these hard-crashes the runner. They are NOT catchable with try/catch. **The one-risky-member-per-call bisect rule applies to read-only PROBES too, not just mutations** — a probe that bundles five unproven members and crashes teaches you nothing (stdout is discarded on a crash) and costs several calls to unpick. Probe with proven-safe members plus at most one unproven member.

> **Nothing you did before a crash reaches you** — the process dies, `stdoutOutput` and
> `exceptionMessage` both come back empty (and `Console` is rejected by the sandbox anyway;
> see [`lambda-contract.md`](lambda-contract.md) § "Sandbox" for the throw-probe). You cannot trace a crash; you can only **bisect by
> shrinking the lambda** until it saves, then re-add one construct at a time. Because a
> crashed mutation rolls back cleanly and the session pointer does not advance, building
> incrementally (many small `applyModelApiCode` calls) is far cheaper than debugging one
> large one.
- **`Func<…>` delegates that create or return Model-API objects crash.** `Action<…>` delegates are fine; inline `for`/`foreach` loops are fine. Never wrap entity/node/widget creation in a `Func`; use `Action` or inline.
- **`(dynamic)` dispatch on a Model-API object crashes the runner** (verified 2026-07-31: `((dynamic)placeholderContent).CreateWidget<IContainer>()` → empty stdout + empty `mutatedOmlPath`). This bites when you've stashed a model object in an `object`-typed variable to carry it out of a `foreach` and then need a generic method on it. **Fix: never widen to `object` — restructure so the work happens inside the loop where the `var` is still statically typed**, or re-fetch it typed. Reflection is rejected by the sandbox; `dynamic` crashes.
- **`*Attribute` getters on a FETCHED (previously-saved) entity crash**: `entity.IdentifierAttribute` / `OrderByAttribute` / `LabelAttribute` / `IsActiveAttribute`. Use `entity.Attributes.Named("X")` instead. (`.IdentifierType` is safe on a fetched entity; on a FRESH `CreateServerEntity` the `IdentifierAttribute` getter safely returns null.)
- **`IMobileScreen.ClientActions` crashes.** The correct accessor for existing screen actions is **`screen.ScreenActions`** (`.Named("Save")`). `screen.ScreenAggregates` and `screen.LocalVariables` are fine.
- **Unqualified `IExpression` in `CreateWidget<T>()` crashes** (verified live 2026-08-03). The sidecar pre-imports `OutSystems.Model.Expressions`, which also declares an `IExpression` — so `CreateWidget<IExpression>()` binds the wrong type **even when `ServiceStudio.Plugin.NRWidgets` is in `imports`**, and dies without a compile error. Always write **`CreateWidget<ServiceStudio.Plugin.NRWidgets.IExpression>()`** in full. `IContainer` and `ITextWidget` have no such collision and are safe unqualified. When in doubt, fully-qualify the widget type — an ambiguity here costs a whole round-trip to isolate.
- **`IMobileBlockInstanceWidget.MarginTop`/`MarginBottom` setters crash.** Use `CustomStyle="margin-top:…;"`.
- **Enumerating a referenced module's static-entity `.Records`** (e.g. `osui.Entities.OfType<IStaticEntitySignature>().Named("AnimationType").Records`) crashes. Set the value and let `getValidationMessages` confirm valid records instead.
- **`AggregationType.Average` crashes** (verified live 2026-08-03). The member that works is **`Avg`** — `agg.AggregationType = AggregationType.Avg;`. `Average` compiles (so you get no `CS0117`) but is not handled downstream. `Sum`, `Count`, `Max` and `Avg` are verified live; `Min` and `None` are listed in the generated enum but untested. Generally: an enum member existing in [`../docs/OutSystems.Model.Enumerations.Generated.cs`](../docs/OutSystems.Model.Enumerations.Generated.cs) is the reliable signal — prefer the exact spelling listed there over a plausible synonym.
- Reflection (`GetProperty`, `GetMethod`, `Invoke`, …) is **rejected by the MCP sandbox** before compiling. Access members through the TYPED variable (e.g. `IDatabaseAggregate.Filters`); typed replacements for the old recipes are listed in [`lambda-contract.md`](lambda-contract.md) § "Sandbox".
- **Recursively walking `.Widgets` to introspect a tree crashes** — `.Widgets` on a leaf widget hard-crashes the runner. To inspect a block/screen, read ONE level and only descend into widgets you've `as`-cast to a container type (`IContainer`, placeholders, `IIfWidget` branches). To learn a block's shape, instantiate it on a scratch screen and print `InputParameters`/`PlaceholdersContent` names (not the widget tree).
- **Mixing manual `((IActionNode)prev).Target = end` with `node.Below(ref, offset)` crashed the runner** in a live run (empty stdout + empty `mutatedOmlPath`). For node wiring prefer the `Connected*` helpers (they set Target + position together); for custom placement set `node.HorizontalPosition`/`VerticalPosition` explicitly (both are settable ints). Don't hand-cast to set `.Target` unless a `Connected*` helper can't express the edge.
- **Binding a chart's `DataPointList` via `new ExpressionDefinition.TypeConversion(source, [...])` hard-crashes** (verified 2026-07-28; the exact syntax in `AddDashboardScreenWithDonutChart.cs` compiles but crashes the sidecar). Bind it with the **parser** instead: `inst.SetArgumentValue(block.InputParameters.Named("DataPointList"), OutSystems.Model.Expressions.ExpressionDefinition.Parse("GetX.List mapTo { Value: <aggAlias>, Label: <aggAlias> }"))`. The `mapTo` right-hand side uses the aggregate's **output aliases** (bare, per-row). Works for Donut/Column/Line/Pie/Bar/Area.

## Discover before you build: ONE probe lambda, not N failures

The dominant cost in a screen build is **learning the API surface one failure at a time**. Writing a build that *hedges* against unknowns (reflection fallbacks for a method that may not exist, `Enum.TryParse` for a member name you're unsure of, name-matched placeholder lookups you can't verify) does not avoid the round trips — it defers them to `getValidationMessages` and runner crashes. Verified 2026-07-31: a dashboard build took 13 `applyModelApiCode` calls; four of them were discovering things one probe would have printed at once.

**Spend one cheap lambda first and print everything the build will touch:**

- the layout block's `PlaceholdersContent` names — **never assume `MainContent`/`Header`/`Footer`**; names vary by app template (one live `LayoutTopHeader` also carries `Breadcrumbs` and `Dashboard`)
- `InputParameters` names of every screen you'll navigate to (a link must satisfy the mandatory ones)
- the exact member spelling of any enum you're guessing (`Avg` vs `Average`) — read it from [`../docs/OutSystems.Model.Enumerations.Generated.cs`](../docs/OutSystems.Model.Enumerations.Generated.cs) (`System.Enum.GetNames` is sandboxed out)
- for each block you'll instantiate: the signature's `InputParameters` names **and** a scratch instance's `PlaceholdersContent` names
- **the default children a fresh widget ships with** (see the widget facts below — several are non-empty)
- the **data types** of every attribute used in a filter or expression
- **`eSpace.References` enumerated, plus the block signatures of each reference you depend on** — the only trustworthy availability check

Scratch screens are free: `flow.CreateScreen("ZzProbe")` … inspect … `scratch.Delete()` in the same lambda leaves nothing behind.

Then **assert the resolved shapes inside the build lambda itself** (print resolved names, data types, link counts) rather than assuming and letting validation catch it — the lambda is already running, so the information is free.

## Reactive widget facts
- **List widget = `ServiceStudio.Plugin.NRWidgets.IList`** (NOT `IMobileListWidget`, which crashes). `list.SetSource("GetX.List")`; add the row template with `list.CreateWidget<IContainer>()` (or a block instance). Bind `GetX.List.Current.<Entity>.<attr>`.
- **`IIfWidget`** (`OutSystems.Model.UI.Mobile.Widgets`): `.SetCondition("…")`, then `.TrueBranch.CreateWidget<T>()` / `.FalseBranch.CreateWidget<T>()`.
- **Dropdown = `NRWidgets.IDropdown`**: `SetVariable`, `SetList("GetX.List")`, `SetValues`, `SetLabels`, `SetEmptyValue`. **Values/Labels are per-item scope — reference the record by ENTITY NAME: `SetValues("Room.Id")` / `SetLabels("Room.Name")`, NOT `GetX.List.Current.Room.Id`** (that fails validation "Can't identify GetX"). The List (Options) DOES use `GetX.List`.
- **Input = `NRWidgets.IInput`**: `SetEnabled("True")`, `.InputType = NRWidgets.Enumerations.InputType.{Text|Password|Number|Time|Date|Datetime|Phone|Email|Search}` (DateTime = `Datetime`), `SetVariable`, `SetMandatory("True")`. Long text → `ITextArea`.
- Fresh `ILabel` has a default `ITextWidget` child → set `((ITextWidget)label.Widgets.First()).Text`. Wire `label.TargetWidget = input` (accessibility). Fresh `IButton` also has a default text child.
- **`ILink` also ships one default child** — runtime type `ServiceStudio.Model.NRWebWidgets+Text` (verified 2026-07-31). Set its text rather than adding a second widget, typed: `lnk.Widgets.OfType<ITextWidget>().First().Text = "Go";` (verified 2026-09-30; a fresh `IButton` ships the same `Text` child). If you want an `IExpression` in the link instead of literal text, delete the default child first or you ship both.
- **A fresh OSUI `Submenu` instance ships a stray default `ILink` in its `Items` placeholder.** Leave it and validation reports `RequiredPropertyValue_Property: On Click must be set`, plus the nav renders a duplicate entry — **delete it after instantiating**. `Submenu` has one input (`ExtendedClass`) and placeholders `Menu` + `Items`; a leaf nav entry puts a single `ILink` in `Menu` and leaves `Items` empty. Generalise the lesson: **assume nothing about a fresh block instance's placeholders being empty** — print them (see "Discover before you build").
- **Icon = `NRWidgets.IIcon`**: `.Icon="building"` (FontAwesome-style names: building/calendar/clock-o/user/home/…), `.IconSize = NRWidgets.Enumerations.IconSize.FontSize`.
- **Block instance**: `parent.CreateWidget<IMobileBlockInstanceWidget>()`; `inst.SourceBlock = <IMobileBlockSignature>`; fill `inst.PlaceholdersContent.First(p=>p.Placeholder?.Name=="Content")`; block inputs via `inst.SetArgumentValue(block.InputParameters.Named("X"), "expr")`. Resolve a referenced block: `eSpace.References.Named("OutSystemsUI").MobileFlows.Named("<flow>").Nodes.OfType<IMobileBlockSignature>().Named("<Block>")`. Discover a block's real placeholders/inputs by instantiating it on a throwaway screen and printing `PlaceholdersContent`/`InputParameters`, then delete the scratch screen.
- Link/Button nav: `widget.OnClick.Destination = screenOrScreenAction; .SetArgumentValue(target.InputParameters.Named("RoomId"), "expr"); .BuiltInValidations = Enumerations.ValidationBehavior.ValidateAndContinue`. Screen actions triggered by a Link can take input params.
- Refresh an aggregate from a screen action: `IRefreshDataNode`, `.DataSource = screenAggregate`.

## Screen scaffolding recipe
`mf = eSpace.MobileFlows.Named("MainFlow"); scr = mf.CreateScreen("X"); scr.Widgets.ToList().ForEach(w=>w.Delete());` then `scr.Roles.Add(eSpace.Roles.Named("Admin"))` (screen-level role gate → redirects unauthorized users to `InvalidPermissions`), `scr.CreateInputParameter(...)`, `scr.CreateScreenAggregate(false,"GetX")` (first bool = isClientSide; `true` only for Local Storage entities), `scr.OnInitialize.Destination = <screenAction>`. Set canvas position `scr.HorizontalPosition`/`VerticalPosition` (ints) or all screens stack at the same coordinate. The app home/default screen is NOT settable via Model API (set it in Service Studio).

## Flow-canvas layout (set positions as you build — don't leave it messy)
Model-API-created diagrams look tangled unless you position nodes deliberately. Do it during the build, not as a rescue pass.
- **Screens in a flow** overlap at a small coordinate scale — the canvas uses **thousands** of units per node. Lay screens out in a grid with generous spacing (≈`dx 2600`, `dy 1500`, base ≈`800`): `scr.HorizontalPosition = 800 + col*2600; scr.VerticalPosition = 700 + row*1500;`.
- **`If`/decision branches in an action**: put the side branch `ToTheRightOf(ifNode)` and the merge/End `Below(ifNode)`. If you instead place the true-branch nodes `Below` the If (same column as the false connector), the connector runs straight through them → overlap.
- **A node created with no positioning defaults to the origin (0,0)** and overlaps the Start/guard nodes. When a node isn't wired via a `Connected*` helper (e.g. an `If`'s `TrueTarget` you set manually), give it an explicit position (`node.HorizontalPosition/VerticalPosition`, relative to the reference node) so the chain that follows via `ConnectedBelow` doesn't start on top of the guard.

## Client vs server, joins, many-to-many
- **Role-check functions (`CheckAdminRole()` etc.) are SERVER-SIDE ONLY** — valid in server-action expressions, but a client/widget expression (menu visibility, screen widgets) errors "Unknown function". To gate UI client-side: a server action returns `IsAdmin` into a local var in OnInitialize; bind widget `SetVisible` to it.
- **The `Common\Menu` block ships EMPTY** and filling the layout `Header`/`Navigation` placeholder with it does NOT create menu items — you add `ILink`s yourself. It's shared across all screens. **Add them to the `PageLinks` container, which is nested inside the Menu's `AdvancedHtml.Content` — NOT the top-level container.** Verified path (2026-07): `menu.Widgets.OfType<IAdvancedHtml>().Single().Content.Widgets.OfType<IContainer>().Named("PageLinks")`. The Menu also has a separate **top-level** unnamed `IContainer`; `menu.Widgets.OfType<IContainer>().First()` returns THAT one, and links placed there render outside the intended nav list (a real bug hit in a live build). `AdvancedHtml.Content` also contains a `LoginInfo` container. Give links the theme's native styling by leaving `CustomStyle` unset.
- **Show a static-entity FK label in a list**: add the static entity as a second aggregate source + a join (`dba.CreateSource(BookingStatus)`; `j=dba.CreateJoin(); j.LeftSource=dba.MasterSource; j.RightSource=bsSrc; j.JoinType=JoinType.Inner; j.SetCondition("Booking.BookingStatusId = BookingStatus.Id")`), then reference `GetX.List.Current.BookingStatus.Label`.
- **Optional related data / M2M display = LEFT JOIN** with the filter INSIDE the join condition (not a WHERE filter): `j.JoinType=JoinType.Left; j.SetCondition("RoomAmenity.AmenityId = Amenity.Id and RoomAmenity.RoomId = RoomId")`; unmatched right row reads `.RoomAmenity.Id = NullIdentifier()`. No calculated attributes needed.
- **M2M editing pattern (reliable): "toggle per row" (immediate write), NOT a batch checkbox-list saved on submit** (the batch pattern needs a client structure-list built in OnAfterFetch — async-timing fragile). Use a `<Link>_Toggle(ParentId, ChildId, LinkId)` server action (delete link if `LinkId <> NullIdentifier()` else create) + a per-row link `If(Current.Link.Id <> NullIdentifier(), "✓ Assigned", "+ Add")` + RefreshData. Gate the section on `ParentId <> NullIdentifier()`. Entity `DeleteAction` input param is named `Id`.

## The aggregate auto-rename trap
Adding a **navigation-style filter** (`Entity.attr <op> ScreenInput`, e.g. `Room.Capacity >= MinCapacity`) to a **default-named** screen aggregate (`Get<EntityPlural>`, e.g. `GetRooms`) **silently renames it** (→ `GetRoomsByCapacity`), dangling every `GetRooms.*` widget reference. Service Studio also re-applies this rename on merge. After adding such a filter, check `screen.ScreenAggregates` names and either update references or rename back with the typed setter (`agg.Name = "GetRooms";` — verified 2026-09-30). Non-default names are immune.

## MCP disconnect recovery
If `MCP server "servicestudio" is not connected` occurs mid-session, the in-process **session-pointer chain is lost** on reconnect — reads/writes then re-snapshot the LIVE open module, which is only as current as the last merge the USER accepted. Unaccepted `omlMerge`s are gone from the chain. Recovery: `%TEMP%\ServiceStudio.MCPServer\<hash>-out.oml` snapshots persist — `omlMerge` the last full one to restore state (user must accept), then `omlReset` + a read to re-seed the pointer, then continue. **Merge frequently** so accepted checkpoints exist, and verify state after reconnect by reading a screen's `ScreenActions`/`ScreenAggregates` before assuming edits are present.
